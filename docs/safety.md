# Safety

What this lab does and does not do, in one page. The tests named here fail if it stops being true.

- **Nothing leaves the machine.** A mock gateway, a mock IAM evaluator, a mock Bedrock, a mock Vertex AI and a lab clock; the netguard refuses every outbound route and records the attempt (`server/test/netguard.test.js`; the doctor runs every scenario under it and asserts zero attempts). Hosts named anywhere in the lab are `.example` or `.invalid` (`server/test/static.test.js`).
- **Loopback only.** The server binds `127.0.0.1` unless `PBA_BIND` is set on purpose; the Host header must be a loopback name or on `LAB_ALLOWED_HOSTS` (421 otherwise); a write must be same-origin (403 otherwise). Docker publishes `127.0.0.1:7838` only and the image runs as the non-root `node` user with a read-only file system and no capabilities (`scripts/compose.test.mjs`).
- **No credential anywhere.** An assumed-role key has no credential field at any depth and refuses one by any name. A stored-credential key holds a write-only `MOCK-` placeholder that is never returned, logged, audited or put in a trace (`server/test/keyModes.test.js`, `server/test/trace.test.js`). The values shown as credentials in a trace are labelled lab mocks. The external ID is never shown in a trace, an audit entry or a log line.
- **Placeholder ids only.** Account ids are made-up digit runs from a short allowlist, names start with `example`, service accounts end in `.example`. A real-looking value is refused, not echoed (`server/test/static.test.js`). Never paste a real ARN, role name, external ID or credential into the page.
- **Policy text is data, never code.** It is parsed with `JSON.parse`, bounded (10000 characters, depth 8, 600 values, 20 statements) and never reaches `eval`, `Function` or `vm` (a static test scans for them). A bad policy is a named result, never a pass.
- **Hostile input is bounded.** A prompt is a string of at most 20000 characters; bodies over 256 KB are refused; workspace ids are 1 to 32 lowercase letters, digits and dashes and at most 20 exist besides the default one. Error messages never echo what the caller sent. User text is rendered as text by React and passed through `visible()`, so control and bidi characters show as escapes.
- **The web page is the only thing served besides `/api`.** The page is served from `web/dist` with a content-security policy (`default-src 'self'`); a missing `/assets` file is a 404 and never the page. The tests run without a web build.
- **Nothing is claimed beyond the release notes.** The MOCK modal that opens the page says what is simulated and that the rest is UNVERIFIED (the `Limits (UNVERIFIED)` tab is named in the nav on every page); the Limits page lists what the release notes say and what is the lab's own model (UNVERIFIED). The lab makes no claim about a gateway's own rate-limit refusals.
- **Real mode is not built.** The header toggle shows Real disabled with the reason, and `POST /api/mode {"source":"real"}` answers 409 with the same words. Real, when it exists, is owner-run and read-only.
